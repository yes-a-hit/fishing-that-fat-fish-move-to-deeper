# 计划：项目级 RAG 索引（2026-11-07）

> 这份是**计划**，不是实现。实现见 `tools/rag_index.py`，产物见 `docs/rag/`。
> 原则：**先材料，后开工**；能查表就不搜索；一次只做一件最小的事。

## 1. 要解决什么

现在会话里每问一个「某某逻辑在哪」，都得 `glob` / `grep` 整个工程，一次几百行输出、
几千 token，还常常白搜。已有的 `assets/art/manifest.json` 只覆盖美术。

目标：**任何「在哪 / 有什么 / 谁调用谁」的问题，先查一张小表**，再决定要不要读文件。

## 2. 范围（只做这些）

| 类别 | 源 | 抽什么 |
|---|---|---|
| 代码 | `scripts/**/*.gd` | 文件行数、`class_name`、`extends`、`func` 名+行号、`const` 名、文件头 `##` 注释 |
| 测试 | `tests/*.gd` | `_case_*` 用例名（就是断言分组） |
| 数据 | `data/**/*.json` | 顶层 key、数组长度、条目 id |
| 文档 | `docs/**/*.md` | 一级/二级标题、行数 |
| 美术 | `assets/art/manifest.json` | 直接并入，不重扫 |
| 场景 | `scenes/*.tscn` | 根节点类型、挂的脚本 |

**不做**：向量化、embedding、外部服务、增量监听、语法树解析。就是 `正则 + 一次遍历`。

## 3. 产物

```
docs/rag/
  MAP.md           人读：目录树 + 每文件一行摘要 + 常用查询示例
  project.json     机器读：{files:[{path,kind,lines,symbols,summary}], stats}
  USAGE.md         检索协议：什么情况查哪张表，怎么只读局部行
tools/rag_index.py 生成器（幂等，跑一次几秒）
```

预算：`project.json` ≤ 400 KB，`MAP.md` ≤ 60 KB。超了就是抽得太细，削字段。

## 4. 检索协议（这是省 token 的正题）

1. **找功能**：先 grep `docs/rag/MAP.md` 的摘要行 → 得到文件路径。
2. **找函数**：读 `project.json` 里该文件条目的 `symbols` → 拿到行号。
3. **读代码**：`read(path, offset=行号-8, limit=60)`，只读那一段。
4. **找美术**：查 `assets/art/manifest.json`，按 `character`/`form`/`group` 过滤。
5. **找数值**：查 `data/**` 的顶层 key（索引里有），再读那一个文件。
6. 以上都不中，才允许全仓 grep；grep 命中超过 3 个文件时，先补索引再读。

## 5. 验收

- [x] `python tools/rag_index.py` 能跑，重复跑结果一致（幂等）
- [x] `docs/rag/project.json` 覆盖 `scripts/` 100% 文件、`data/` 100%、`docs/` 100%
- [x] 任取 3 个问题（某函数在哪、某数值在哪、某立绘在哪），纯靠索引能在 1 次读取内定位
- [ ] 接入 `docs/contributing.md`：新增文件后要跑一次索引（下一步做）

## 6. 明确不做（避免工程量失控）

- 不做向量库、不装依赖、不联网
- 不解析 GDScript 语法树（正则够用，`func`/`const`/`class_name` 都在行首）
- 不改任何业务代码；索引是纯旁路产物
- 不在 CI 里跑（本地手动，几秒的事）
